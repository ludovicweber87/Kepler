# Auto-rename du worktree façon Orca

**Date** : 2026-07-23
**Statut** : design validé (en attente de plan d'implémentation)

## Contexte & problème

Devora renomme la branche/worktree d'une session depuis le premier prompt de
l'utilisateur (`wip-sharp-canyon-0lxb` → `feat-add-login`). Cette fonctionnalité
**fonctionnait le 22/07** (via un ancien mécanisme produisant des slugs français)
puis a été **remplacée le 23/07** par un nouveau système SDK (commits persona
#120→#125 : `packages/agent/src/sdk/autoRename.ts` + câblage dans
`sdkAgent.ts`).

Depuis ce remplacement, **plus aucune session non-issue n'est renommée** : 8
sessions du 23/07 restent bloquées en `wip-`. Investigation (tests réels sur
`~/.devora/devora.db`) :

- `readSessionRow` / `readFirstUserText` lisent correctement le 1er prompt ✓
- `generateBranchSlug` via `claude --print --model haiku` renvoie un slug valide
  en ~8,8 s ✓
- `autoRenameBranch` end-to-end renomme et persiste ✓

**Les briques marchent isolément ; le rename ne "land" jamais dans le process
serveur en live.**

### Root cause identifié (env du sous-process)

`cleanEnv()` (chemin SDK, `sdkAgent.ts:82-90`) supprime **5** variables avant de
lancer l'Agent SDK : `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`,
`ANTHROPIC_BASE_URL`, `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT` — parce que le SDK
utilise sa propre auth (login CLI stocké). Mais `defaultRun` (`autoRename.ts:71-83`,
qui lance `claude --print --model haiku`) n'en supprime que **2** (`CLAUDECODE`,
`CLAUDE_CODE_ENTRYPOINT`).

Conséquence : en live, le sous-process `claude --print` **hérite** de
`ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_BASE_URL` du serveur agent →
auth/endpoint incohérent → génération échoue → `generateBranchSlug` renvoie
`null` → rename abandonné (retry différé), silencieusement.

**Pourquoi l'investigation en shell/tsx réussissait** : un shell de dev ne
définit **aucune** var `ANTHROPIC_*`, donc le sous-process partait déjà avec un
env propre. Le bug n'apparaît que dans le process serveur `devora` (où ces vars
sont injectées pour le SDK). CQFD : « marche isolément, jamais en live ».

Le trigger n'était pas silencieux sur ce point : `generateBranchSlug` logge déjà
l'échec (`autoRename.ts:98,101`). Le seul vrai trou de logs est côté
**gates/trigger** dans `maybeStartAutoRename` (returns sans log).

## Objectif

Réécrire l'auto-rename en s'inspirant du modèle d'Orca
(`stablyai/orca`, `src/main/agent-hooks/first-work-branch-rename.ts`), en :

0. **corrigeant le root cause** (P0) : aligner l'env du sous-process `claude
   --print` sur celui du SDK (`defaultRun` doit stripper la **même** liste que
   `cleanEnv`). C'est le fix qui débloque réellement le rename en live ;
1. **rendant le chemin observable** : logs de gate/trigger dans
   `maybeStartAutoRename` (le seul trou de logs) — permet de confirmer le fix et
   de diagnostiquer tout futur bail ;
2. **ajoutant les garde-fous d'Orca** (gate upstream + re-validation post-génération) ;
3. **affichant un nom humanisé dans la sidebar** (le principal apport visuel d'Orca).

Le moteur de génération (`claude --print --model haiku`, slug typé anglais) est
**conservé sur sa logique** ; seul son **env** est corrigé (P0).

## Décisions produit (validées)

| Décision | Choix | Justification |
| -------- | ----- | ------------- |
| Style du slug | **Typé** `feat-`/`fix-`/`refactor-`/`docs-`/`test-`/`chore-` | Conventionnel, cohérent Git ; meilleur qu'Orca (freeform) sur ce point. Inchangé. |
| Langue | **Anglais forcé** | Branches en anglais = standard. Règle actuelle conservée (`SLUG_RE`, prompt "translate"). |
| Nom affiché sidebar | **Humanisé dans `agent_name`** si vide | Équivalent Devora du `setDisplayName` d'Orca. La sidebar affiche `agent_name || branch`. |

## Mapping Orca → Devora

| Concept Orca | Équivalent Devora |
| ------------ | ----------------- |
| Nom placeholder créature (`Nautilus`) | préfixe `wip-` |
| `isAutoGeneratedCreatureBranchName` | `isAutoNamed(branch)` = `startsWith('wip-')` |
| Hook `first-work` sur state `working` | `maybeStartAutoRename` (déjà appelé à l'envoi du 1er message + fallback `result`) |
| `probeBranchUpstream` (gate + re-check) | **NOUVEAU** : `branchHasUpstream(worktreePath)` |
| Génération via CLI agent | `claude --print --model haiku` (conservé) |
| `humanizeBranchSlug` | **NOUVEAU** : `humanizeBranchSlug` (avec strip du préfixe de type) |
| `setDisplayName` (si display encore auto) | **NOUVEAU** : `persistAgentName` si `agent_name` vide |
| Logs `[auto-branch-rename] skip (reason)` | **NOUVEAU** : logs verbeux de skip/retry |

## Changements par composant

### `packages/agent/src/sdk/autoRename.ts`

- **P0 — `defaultRun`** : stripper la même liste que `cleanEnv` (ajouter
  `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`). Idéalement
  factoriser la liste en une constante partagée pour éviter la re-divergence.
- **`humanizeBranchSlug(slug: string): string`** — `feat-add-login` → strip du
  type conventionnel en tête (`feat`/`fix`/`refactor`/`docs`/`test`/`chore`,
  sans ambiguïté car `SLUG_RE` garantit `<type>-<mots>`) → `add-login` →
  `Add login`. Retourne `''` si rien d'exploitable.
- **`branchHasUpstream(worktreePath, exec?)`** — `git rev-parse --abbrev-ref
  --symbolic-full-name @{upstream}` : succès ⇒ a un upstream (skip), échec ⇒ pas
  d'upstream (procède). **Nécessite un nouveau seam d'exécution** (paramètre
  `exec`, sur le modèle du `run` de `generateBranchSlug`) : les helpers git
  actuels appellent `execFileSync` en dur et ne sont pas testables — il faut
  donc introduire ce seam pour rendre le gate testable. Gate **avant** + **re-validation
  après** la génération.
- **`readAgentName(sessionId)` / `persistAgentName(sessionDbId, name)`** —
  lecture/écriture de `agent_sessions.agent_name`.
- **`autoRenameBranch`** enrichi :
  - gate upstream avant génération (skip si publiée) ;
  - re-validation après génération : branche inchangée ET toujours sans upstream
    (sinon abandon, retry plus tard) ;
  - après `git branch -m` + `persistBranch` : si `agent_name` **vide** ET
    `humanizeBranchSlug(newBranch)` **non vide**, écrire via `persistAgentName`
    (garde double : jamais d'écrasement d'un label persona/issue, jamais
    d'écriture vide) ;
  - retourne un verdict structuré (`{ outcome: 'renamed'|'skip'|'retry', reason }`)
    pour permettre le logging côté appelant.
- **Contexte de génération** : passer aussi la 1re réponse de l'agent
  (`assistantMessage`) au prompt quand elle existe. **Portée : chemin `result`
  uniquement** — au trigger immédiat (envoi du 1er message) aucune réponse agent
  n'existe encore, et aucun helper `readFirstAssistantText` n'existe (à créer).
  Cela touche `buildBranchNamePrompt`/`SLUG_RE` : à retirer de la liste « ne
  change pas ».

### `packages/agent/src/sdk/sdkAgent.ts`

- **`maybeStartAutoRename`** : logger chaque décision de **gate/trigger** avec sa
  raison (`[auto-rename] skip (branch has upstream) for <id>`,
  `retry-later (generation failed) …`, `renamed <wip> -> <feat>; display "<x>"`).
  C'est le seul trou de logs (la génération/git loggent déjà leurs échecs).
- **Contrainte** : la réécriture de `maybeStartAutoRename` **doit préserver** le
  garde anti-double-déclenchement en tête (`if (s.renameInFlight || s.pendingMove)
  return;`) + le `!s.renameInFlight` du chemin `result` — sinon deux générations
  concurrentes.
- Câbler la mise à jour du display name (via le retour enrichi de
  `autoRenameBranch`) — aucune nouvelle broadcast nécessaire : la sidebar poll
  les sessions toutes les ~5 s (`useAgentSessionHistory`, confirmé
  `useAgentSession.ts:231`), l'UPDATE DB suffit.

## Comportements assumés

- Une session issue (branche **non**-`wip-`) sort de `autoRenameBranch` avant
  toute écriture ⇒ jamais humanisée. Idem une session dont le flux « title »
  (`api/agent-sessions/log/route.ts:50-57`) a déjà forcé `agent_name` : le garde
  « si vide » empêche l'écrasement. **C'est voulu.**

## Ce qui NE change pas

- Le préfixe `wip-` et `randomWorktreeName()` (marqueur d'éligibilité).
- Le déclenchement immédiat à l'envoi du 1er message + fallback `result`.
- La commande `claude --print --model haiku` (seul son **env** est corrigé, P0),
  `dedupeSlug`, `moveWorktreeDir`, `applyWorktreeMove`.
- Le flux issue (`generate-branch-name`) — indépendant.

## Vérification (obligatoire — c'est une régression live)

Le design n'est **pas "fini"** tant qu'un rename réel n'a pas été observé :

1. Lancer le serveur agent + une session sans persona ni issue.
2. Envoyer un premier prompt.
3. Confirmer dans `~/.devora/devora.db` : `branch` passe de `wip-…` à `feat-…`,
   `agent_name` reçoit le nom humanisé, le dossier worktree est déplacé.
4. Confirmer que la sidebar affiche le nom humanisé.
5. Si toujours en échec : les nouveaux logs `[auto-rename]` donnent la raison
   exacte (trigger non atteint / génération échouée / gate) → fix ciblé.
