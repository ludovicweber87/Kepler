# SQLite Migration — Replace Supabase with Local SQLite

**Date:** 2026-03-21
**Status:** Approved
**Scope:** Migration pure — same features, remove Supabase dependency

## Context

Devora is a personal development dashboard — single user per instance. Supabase (PostgreSQL cloud) adds unnecessary complexity: network dependency, env vars, RLS policies, JWT tokens. SQLite local is a better fit.

## Decision

Replace Supabase with **SQLite** (via `better-sqlite3`) + **Drizzle ORM** for type-safe queries and versioned migrations. Database file lives at `./data/devora.db` (gitignored).

## Schema

6 tables, same structure as Supabase minus `user_id` (no longer needed):

```typescript
// src/db/schema.ts

todos
  id: integer (PK, autoincrement)
  repo_full_name: text (not null)
  title: text (not null)
  description: text
  done: integer (boolean, default 0)
  sort_order: integer (default 0)
  issue_number: integer
  issue_repo: text
  created_at: text (ISO timestamp, default now)

agent_sessions
  id: integer (PK, autoincrement)
  session_id: text (not null, unique)
  project_path: text
  project_name: text
  branch: text
  agent_name: text
  status: text (default 'active')
  created_at: text (ISO timestamp, default now)
  updated_at: text (ISO timestamp, default now)

agent_activity_logs
  id: integer (PK, autoincrement)
  agent_session_id: text (not null, FK → agent_sessions.session_id)
  content: text
  log_type: text
  branch: text
  status: text
  created_at: text (ISO timestamp, default now)

repo_paths
  id: integer (PK, autoincrement)
  repo_full_name: text (not null, unique)
  local_path: text (not null)

project_configs
  id: integer (PK, autoincrement)
  config: text (JSON stringified)
  created_at: text (ISO timestamp, default now)

tab_orders
  id: integer (PK, autoincrement)
  group_key: text (not null, unique)
  order: text (JSON stringified)
```

## File Structure

```

├── schema.ts         # Drizzle table definitions (sqliteTable)
└── migrations/       # auto-generated by drizzle-kit
data/

```

## What Changes

| Before (Supabase) | After (SQLite) |
|---|---|
| `lib/supabase.ts` — Supabase client init | `src/db/index.ts` — Drizzle + better-sqlite3 instance |
| `lib/supabase-jwt.ts` — JWT token creation | **Deleted** |
| `/api/supabase-token` route | **Deleted** |
| `NEXT_PUBLIC_SUPABASE_URL` env var | **Removed** |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` env var | **Removed** |
| `supabase.from('todos').select()...` | `db.select().from(todos)...` |
| RLS policies (user_id filtering) | Nothing — local file |
| Network round-trip per query | Local file read (~0ms) |

## What Does NOT Change

- Hook public APIs remain identical (components see no difference)
- React Query stays as the caching layer
- API route URLs stay the same
- NextAuth stays for GitHub OAuth (still need the token)
- All polling intervals stay the same

## Migration Plan

### Step 1 — Setup dependencies
- `yarn add drizzle-orm better-sqlite3`
- `yarn add -D drizzle-kit @types/better-sqlite3`
- Add `data/` to `.gitignore`

### Step 2 — Schema & DB init
- Create `src/db/schema.ts` with all 6 tables
- Create `src/db/index.ts` — init better-sqlite3 pointing to `./data/devora.db`, auto-create `data/` dir if missing, export Drizzle instance
- Create `drizzle.config.ts`
- Run `drizzle-kit generate` for initial migration

### Step 3 — Migrate hooks (server-side queries)
Replace Supabase calls with Drizzle in:
- `useTodos` / `useDashboardTodos` — CRUD todos
- `useAgentSession` — session lifecycle (ensure, addLog, updateStatus)
- `useSessionManager` — aggregate active + past sessions
- `useRecentLogs` — summaries, log parsing
- `useProjectConfig` — CRUD project config
- `useRepoPaths` — repo ↔ local path mapping
- `useTabOrder` — tab order persistence

Note: hooks call API routes which call Supabase. The Drizzle calls go in the API routes, not the hooks directly.

### Step 4 — Migrate API routes
Routes that directly use Supabase:
- `/api/agent-sessions/log` (POST) — insert activity log + backfill session
- `/api/agent-sessions/[sessionId]/kill` (POST) — update session status
- `/api/agent-sessions/[sessionId]/auto-summary` (GET) — read logs
- Any other route importing from `lib/supabase.ts`

### Step 5 — Cleanup
- Delete `src/lib/supabase.ts`
- Delete `src/lib/supabase-jwt.ts`
- Delete `/api/supabase-token/` route
- Remove `@supabase/supabase-js` from dependencies
- Remove `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` from env files / docs
- Update CLAUDE.md (stack table, env vars section)

## Data Strategy

Clean start — no migration of existing Supabase data. The DB starts empty. Existing data remains in Supabase if needed for reference.

## SQLite Considerations

- **WAL mode** enabled at init for better concurrent read performance
- **JSON storage** via TEXT columns with `JSON.stringify/parse` (for `config` and `order` fields)
- **Timestamps** stored as ISO 8601 text strings
- **Auto-migration** on app start via `drizzle-kit migrate` programmatically, so the DB schema is always up to date
