Kepler 1.0 · a local app · macOS

Several AI agents on one project.

Kepler is an app that runs on your Mac. It launches several Claude agents on your projects, each in its own copy of the code, and shows you at all times what each one is doing.

curl -fsSL https://raw.githubusercontent.com/ludovicweber87/Kepler/main/install.sh | bash
See how to install →

Free and open source. No account to create, no API key to paste: Kepler reuses the GitHub login you already have on your machine.

When you start an AI agent from your terminal, it works inside your project folder, on the branch you happen to be on. So you can only run one at a time: two agents would edit the same files at once and get in each other's way.

You therefore wait for the first to finish before starting the next. And while it works, you watch text scroll past in a terminal, without really knowing which files it changed or how far along it is.

Kepler gives each agent its own copy of the project. So they all work at the same time.

What Kepler does

Five things, explained plainly.

01

One copy of the project per agent.

Git can create what it calls a worktree: a second folder holding your project, checked out on another branch, but tied to the same repository and the same history. Kepler creates one per agent, automatically.

Two agents therefore never touch the same files. You can run five of them on five different subjects, and the folder you work in yourself is left alone.

  • Create a fresh worktree on a new branch: the usual case
  • Work directly on the branch you are already on, creating nothing
  • Pick up an existing branch, local or remote
  • Or start an agent in any folder at all, with no project and no branch

02

Your instructions, written down once.

A persona is a form you fill in once: a name, a role, the instructions the agent must follow, which Claude model to use, how hard it should think, and whether it may change files without asking you first.

You pick one when you start an agent, and it begins with all of that in mind. No more re-explaining your conventions every time. Kepler ships ten of them, and you write your own.

  • A persona can be limited to certain repositories, or available everywhere
  • You can switch persona mid-conversation: the agent is told, and the discussion carries on where it left off
  • The input box takes the persona's colour, so you can see at a glance who you are talking to

03

Documentation you fix by talking to it.

You describe a subject and choose whether the agent should draw on general knowledge or read one of your repositories. You then set the level, the length and the format. It writes the page while you do something else.

Each document then has its own conversation, shown next to the text. You ask a question, or ask for a correction, and the agent edits the document directly. It only rewrites a passage it has quoted word for word, and refuses to guess when the request is ambiguous.

04

An agent that starts from a GitHub task.

On GitHub, an issue is a task written up in your repository: a title, a description, a discussion. Paste its address when you start the agent. Kepler reads the title and the description, hands them over as the starting point, creates the branch and the worktree, then comments on the issue so the team can see the work has begun.

The agent needs no re-explaining of the task: it has already read it.

  • A board shows your issues: drag a card from one column to another and the status changes on GitHub too
  • The list of your pull requests, with the result of the automated tests and a button to merge
  • Describe a task in one sentence: the agent writes the issue, you create it on GitHub
  • Once the pull request is merged, the issue moves on by itself and the worktree is put away

05

The day's write-up, done for you.

Kepler gathers what happened in a repository over a day: the commits on every branch, the pull requests, and what the agents did. An agent turns that into a few sentences in the first person.

These write-ups appear on a calendar. Click a day and you read the text and, below it, the detailed list it was built from. Enough to prepare a standup without digging through git history.

The rest

What you will find in the app.

◱ The working screen

This is where you spend your time. The conversation with the agent takes the left-hand side. On the right, four tabs show you the files it changed, its activity log, the linked issue and a file explorer. Below that, one or more terminals open up.

◈ A real conversation

Kepler does not drive a terminal on your behalf: it talks to Claude through its official SDK. Every tool used shows up as a card, you grant permissions with one click, and the agent can ask you a question in the middle of its work.

◷ A log you can read

Instead of pages of raw output, Kepler sums up what the agent did: the decisions it took, the files it created or changed, the commits, what blocked it, and a recap at the end.

◔ It tells you

When an agent finishes, fails, or is waiting on your answer, a notification arrives straight away, with a sound and a system notification. So you can start an agent and go do something else.

◫ Nothing gets lost

Close the tab, shut the machine down: when you come back, the conversation, the terminal and the worktree are as you left them. Everything is saved on your disk.

⇅ Your work in one place

You find in one place the board of your GitHub issues, the list of your pull requests with their tests, and a personal to-do list with due dates. A task can point to an issue, or create one.

⌘ Your commands as buttons

Declare the commands you type all the time — run the tests, the linter, the dev server — and they appear as buttons at the top of the screen. Each one opens in a terminal, or goes to the agent as a message.

⚙ Per-repository settings

For each project, you set the files to copy into every new worktree — your .env, for instance —, a script to run on creation, and the standard wording the agent uses to open a pull request.

◐ To your taste

Kepler ships seven colour themes, and a fully adjustable palette if none of them suits you. Fonts and sizes are set separately for the app and the terminal, the interface comes in five languages, and a button opens the worktree in your editor.

Install

Two commands, and you're running.

  1. Run the installer

    curl -fsSL https://raw.githubusercontent.com/ludovicweber87/Kepler/main/install.sh | bash

    The script downloads Kepler into ~/.kepler/repo, builds it, and adds a kepler command to your terminal. You can run it again later: it simply updates.

  2. Reload the terminal, then start

    source ~/.zshrc && kepler start && kepler seed

    The source is what makes the new command known to the terminal you already have open; opening a new tab amounts to the same thing. On bash or fish, swap in ~/.bashrc or ~/.config/fish/config.fish — the script prints the right command when it finishes.

    kepler start opens the app window. kepler seed installs the ten personas that ship with it. There is nothing else to configure.

  3. The first five minutes

    In Settings, say where your projects live on disk. Then, in the left bar, hit + on a project, pick a persona, and describe what you want. To start from an existing task, paste the address of a GitHub issue at launch.

What you need

  • A Mac — Kepler is built and tested there
  • Node 20 to 25 — version 26 is not supported yet
  • gh, GitHub's own tool, connected to your account
  • claude, Claude's command-line tool
  • git and tmux

Where your data lives

In ~/.kepler/: the database, the logs and the service files. Updates never touch it.

The commands

kepler start
Starts Kepler and opens the window
kepler stop
Stops everything
kepler restart
Restarts, after an update for instance
kepler status
Says what is running, and on which address
kepler logs
Shows the logs, when something goes wrong
kepler update
Fetches the latest version
kepler seed
Installs the ten personas that ship with it

Try it on one of your projects.

One command to install, one to start. Kepler is free, runs at your place, and sends nothing beyond what you would already be sending to Claude.
