The five pillars of 1.0

Built around how the work actually happens.

01

A fleet, not an agent.

Every session gets its own isolated worktree under .worktrees/, its own branch and its own terminal, so N agents work at once without ever stepping on each other. The sidebar shows the whole fleet: projects → worktrees → sessions, with a dot on any agent waiting for you.

  • New worktree, on a fresh branch
  • The current branch, as-is
  • An existing branch, local or remote
  • Free mode — no project, just an agent in a folder

02

Personas that carry your conventions.

Stop re-explaining yourself. A persona bundles a name, a role, a system prompt and its own defaults for model, reasoning effort, permission mode and accent colour. Every session launched with it inherits them.

  • Scoped to specific repos, or global
  • Switch persona mid-conversation — no restart, no lost context
  • The composer takes the persona's colour, so you always know who you're talking to

03

Docs you can argue with.

Describe a subject, pick a source — general knowledge or one of your repos — then a level, a length and a format. A writer agent produces the doc in Markdown, in the background.

Then the part that matters: every doc has its own chat, next to the text. Ask a question, or ask for a change — the agent edits the document in place. It only touches a passage it has quoted word for word, and refuses an ambiguous request rather than guessing.

04

Wired into GitHub, not bolted onto it.

Launch an agent straight from an issue. Kepler puts the issue title and body into the session's system prompt, creates the branch and the worktree, and comments on the issue so the trail stays visible on GitHub. The agent starts already knowing what it's for.

  • Projects V2 kanban — drag-and-drop, status synced via GraphQL, cached locally for instant loads
  • Every open PR with CI status and one-click merge
  • AI-drafted issues from a single sentence
  • Post-merge triage — issue moves to your QA column, worktree archived

05

The daily writes itself.

A month calendar of AI-written daily reports, per repository. Kepler collects the day's real activity — commits across all branches, pull requests, agent activity logs — which an agent turns into a handful of first-person bullets.

Cells show the points inline. Click a day for the full report plus the raw activity timeline it was built from. Generate, regenerate or delete any day.

Everything else

The rest of the cockpit.

◱ The Workbench

The agent conversation on the left; Changes, Activity, Issue, Explorer and Reader on the right; multiple terminal tabs below (⌘J) on a draggable split. Files open as tabs next to the chat.

◈ Real SDK sessions

Agents run through the Claude Agent SDK, streamed over WebSocket: tool-call cards, permission requests you approve from the UI, inline questions. Transcripts live in SQLite on the server and replay on reconnect.

◷ Activity timeline

A readable timeline derived from the event stream — decisions, file changes, commits, blockers, and a final summary. Plus a per-session recap when the work is done.

◔ Notifications

When an agent finishes, fails or gets blocked waiting for you, a prioritised, de-duplicated notification lands instantly over SSE — with a sound and an OS notification if you've walked away.

◫ Sessions that survive

Close the tab, restart the machine, come back: the conversation, the terminal and the worktree are still there. Session labels are decoupled from git — and a manual rename always wins over the auto-title.

⇅ Issues, PRs, Tasks

A kanban synced to Projects V2, every open PR with its checks, and tasks with due dates, urgency colouring and pinning. Each task links to a GitHub issue, or creates one.

⌘ Repo scripts

Declare per-repo commands and get them as buttons in the top bar. Each runs in a new terminal tab or as a message to the agent.

⚙ Per-repo settings

Custom create-PR and commit-&-push prompts, files to copy into every new worktree, setup and archive scripts, and the QA column used by post-merge triage.

◐ Themes and fonts

Seven themes plus a full custom palette, independent fonts and sizes for app and terminal, five UI languages, and one click to open any worktree in your editor.

Get started

Two commands, and you're running.

  1. Install

    curl -fsSL https://raw.githubusercontent.com/ludovicweber87/Kepler/main/install.sh | bash

    Clones a dedicated copy into ~/.kepler/repo, builds it, and puts a stable kepler command on your PATH. Re-runnable — running it again updates in place.

  2. The installer put ~/.kepler/bin on your PATH; this shell doesn't know it yet. A new terminal works too. For bash or fish, swap in ~/.bashrc or ~/.config/fish/config.fish — the installer prints the right command when it finishes.
  3. Point Kepler at a repo in Settings, connect a Project V2 board, then hit + on a project and pick a persona. Paste an issue URL at launch to hand the agent its context.

Prerequisites

  • macOS — built and tested there
  • Node 20–25 — native modules aren't on 26 yet
  • gh, authenticated (gh auth login)
  • claude CLI on your PATH
  • tmux and git

Runtime state

The SQLite database, pids and logs live in ~/.kepler/ and survive updates. Optional overrides go in ~/.kepler/.env.

The CLI

kepler restart
